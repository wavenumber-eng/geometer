# Log: Geom A0 contract alignment proposed

Revalidated the digest-locked Geom schema, accepted ADRs 0003 through 0005,
and MATZ requirements packet against the compatibility snapshot. Geometer does
not read those sibling files during generation, builds, or tests.

Added the Geometer-owned mapping report for the reusable analytic planar
subset. It records compatible concepts and deliberate differences for points,
lines, circular arcs, paths, rings, planar regions, disks, annuli, capsules,
and swept paths. It also fixes unit ownership, layered validation, operation
result/provenance ownership, the genericity boundary, and the additive MATZ
migration sequence.

The proposal preserves the already joint-reviewed MATZ fixtures as consumer
evidence without treating the Geom JSON Schema as Geometer authority. The
analytic request/result and packed projection remain unfrozen pending focused
review of this mapping and the subsequent TypeSpec/design step.

Independent review found two adapter ambiguities. The remediated report now
defines radius/sweep arcs as the unique requested-direction minor-or-semicircle
solution and requires an exact integer-nanometer center; every ambiguous,
non-integral, or out-of-range case is rejected. It also defines frozen Geom
capsule length as total tip-to-tip length, derives centerline endpoint distance
as `length - width`, accepts only provable similarity transforms, applies their
uniform scale to width, and requires exact integer-nanometer transformed
endpoints and width. Shear, nonuniform scale, fractional results, and overflow
fail closed rather than varying between adapters.

Focused re-review accepted the deterministic mapping at commit `433bad5` in
packet `reviewer-019ffce8-ac66-76c0-877d-3fcb5c1aa6c5`. The compatibility
snapshot now records that acceptance, `geom-contract-alignment` is complete,
and `analytic-planar-boolean-design` is active. This acceptance freezes only
the alignment report; the operation TypeSpec, packed packet, solver, and
release remain gated.

The next design slice vendors the byte-identical joint-reviewed MATZ
observation manifest at
`tests/fixtures/analytic_planar_boolean/matz_observations_a0.json`. Its digest
remains `10a97f0eed4a4f6852917c4fb6abd35854142bf5d148b8320c60a44f765414c4`.
Focused tests validate its ten portable cases, two real-board observations,
nonzero/bounded and unique identifiers, closed union/difference and geometry
kind inventories, relationship references, twelve-fragment feasibility link,
and declared correctness-first performance budget. No normal test reads the
sibling checkout.

Independent review found that the first structural test checked stage and
operand uniqueness per job even though the fixture declares every ID space to
be batch-scoped. The corrected test collects job, stage, operand, and query IDs
across the entire fixture batch. It recursively classifies every explicit
`source_topology` ring (including `boundary_ring_id`), path, segment, curve,
feature, and vertex ID; each space is independently nonzero, uint64-bounded,
and unique. The compact derived-ID formulas remain policy text because the
fixture deliberately does not materialize those derived feature/vertex IDs.

A second focused review found that Python booleans could satisfy the numeric
comparisons and relationship query IDs lacked an explicit range check. One
shared assertion now requires a non-boolean integer in `1..UINT64_MAX` for all
job, stage, operand, query, relationship-reference, and explicit source ID
values before uniqueness or reference checks.

The analytic TypeSpec candidate is now compiled through a separate entrypoint
so it cannot enter the promoted runtime catalog accidentally. It models the
logical job/stage/operand topology, all fifteen packet-local identity spaces,
analytic result topology, source sets, operand outcomes, job diagnostics, and
relationship results. New emitter metadata explicitly maps the logical request
and result to their named packed attachments and governed packet format. The
candidate check validates both schemas, the normalized catalog, attachment and
projection identities, nonzero uint64 ID scalars, and isolation from the
production generation entrypoint. Manifest status is `typespec_candidate`;
request/result authority, packed bytes, production projections, and solver
implementation remain unfrozen.
