# Log: canonical exact-expression arithmetic feasibility

The exact backend now evaluates canonical addition, multiplication, reciprocal,
and nonnegative square root. Rational operations reduce exactly; mixed
rational/algebraic operations use checked translation and scaling transforms;
and algebraic operations use square-free resultants, deterministic integer
factorization, governed operand refinement, and exact factor/root selection.
Candidate intervals widen by one dyadic unit before open-interval root counting,
so exact rational results on an outward endpoint still collapse to the unique
rational value rather than depending on approximation.

The expression evaluator uses the governed 256, 512, 1024, 2048, and 4096-bit
schedule. Every interval-arithmetic phase has checked, operand-derived work and
temporary-storage reservations. Rational transforms include coefficient growth
from the rational numerator and denominator in their preflight and reject an
estimated coefficient width beyond 16,384 bits before allocation. Root
isolation now charges one deterministic precision phase at a time instead of
requiring the maximum-precision work bound before an easily isolated root can
proceed; work remains monotonic while retained storage and failed transaction
state roll back.

Focused vectors cover rational reduction and domain failures, mixed
translation/scaling, `sqrt(2) + sqrt(3)`, `sqrt(2) * sqrt(3)`, reciprocal and
nested square root, irrational cancellation and rational collapse,
`sqrt(8) / 2` value convergence, negation, oversized transform rejection, and
a platform-independent exact success/one-unit-short work boundary. The same
test executable is registered for native and Emscripten.

The normalized construction DAG, complete `GEXPA001` artifact, geometric
intersection vectors, and production analytic solver remain disabled pending
their own implementation and independent acceptance.
