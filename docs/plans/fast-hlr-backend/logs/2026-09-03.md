# Log: fast-backend-contract

Recovered the clean 6db348c checkpoint. Added Fast vector and Fast mesh shadow selectors to the packaged HLR Lab with independent Detail, Outline, and Both inspection. Extended the benchmark harness to compare native and Node-hosted WASM runtimes using canonical geometry digests. Fast output matched across all five governed package fixtures. BGA90 detail p50 HLR was 59.63 ms native and 114.98 ms WASM; combined prepared view p50 was 77.62 ms and 121.92 ms. One-shot time is dominated by WASM startup and STEP import, strengthening the case for a reusable prepared-data transport before browser interface promotion.

Refined the HLR Lab evaluation surface around the intended contract boundary. A dedicated Fast detail HLR checkbox now switches the raw Detail layer between Fast and the selected OCCT polygonal/exact engine. OCCT-only edge controls and Fast-only candidate/tolerance controls are presented in separate panels, while the Outline algorithm remains independently selectable. The Fast controls populate the provisional nested `fast` options object. The packaged offline site and its governed Chrome/WASM interaction test pass with real Fast detail and Fast mesh-shadow output.

Changed the Fast crease threshold presentation to degrees for evaluation usability while retaining `crease_angle_rad` on the public backend contract. The browser converts the entered degrees to radians before projection.

SOT-223 evaluation exposed that the HLR Worker omitted the nested `fast` options object and that the browser cache key omitted those values. The controls therefore appeared to recompute without changing the backend request. The Worker now passes the Fast block unchanged and the cache keys every Fast option. A governed Chrome/WASM regression selects `sot223.stp` Front view and proves that lowering the threshold from 30 degrees to 10 degrees increases the real Fast detail output.
