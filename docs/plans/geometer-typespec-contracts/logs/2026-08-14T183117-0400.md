# Log: public hosted demonstration gates

The plan now makes the analytic planar Boolean demonstration an explicit gate
for the focused additive release rather than relying on the generic final-demo
closure. The promotion and release steps are separated so the operation first
passes every production client, then ships only after a polished interactive
browser demonstration proves the intended public integration path.

The analytic demo must use the generated TypeScript Worker/WASM client and
curated governed fixtures. It visualizes ordered stages, exact line/arc output,
components and holes, source incidence, material lineage, canonical results,
and structured failures. A second solver, sampled authoritative output, direct
C ABI pointer marshalling, and MATZ/PCB policy are prohibited.

The hosted-demo scope also records the human-requested model-bounds, HLR, and
STEP/GLB public demonstrations. Their final presentation remains unfrozen until
their owning operation reviews, but all four demos share a deterministic,
offline-capable static output and public-safe asset policy. Berkeley Mono and
private consumer data are excluded.

Cloudflare Pages is the planned static host. The deployable prebuilt directory
contains no Pages Functions or other server-side behavior, includes a reviewed
static `_headers` policy, passes desktop/narrow and offline browser smoke, and
has an exact directory digest. The analytic release requires preview and
production deployment evidence; later demos receive the same review at their
own promotion gates.

This governance-only amendment does not enable production solver dispatch.
The OCCT qualification step remains active until its two V8_0_1 dependency
caches are published and restored from clean isolated roots.
