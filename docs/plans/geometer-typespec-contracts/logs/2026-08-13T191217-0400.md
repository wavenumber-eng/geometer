# Log: primitive polynomial and real-root feasibility

Built the next independently authorized exact-backend feasibility layer without
opening the production analytic solver gate.

The new C++17 module constructs budget-owned primitive integer polynomials with
checked degree-64 and coefficient-bit limits, trailing-zero/content/sign
normalization, and typed fail-closed outcomes. It isolates the distinct real
roots of square-free degree-two-or-higher inputs using exact rational Sturm
sequences, Cauchy bounds, and smallest-precision adjacent dyadic cells. Thom
signs are accepted only after an exact derivative-root count proves each
derivative has constant nonzero sign throughout the root cell. Work and logical
storage are conservatively precharged, remain monotonic on executed failures,
and roll back temporary ownership.

Native/Emscripten tests cover primitive normalization, `sqrt(2)` root order and
Thom signs, an exact dyadic precision transition, successful empty real-root
sets, degree/coefficient limits, repeated-root rejection, and resource
exhaustion. Emscripten exact tests use `.cjs` launchers because the repository is
ESM, and native-only executable IPC test servers are no longer incorrectly
linked into the WASM default target. The exception-enabled polynomial/rational
feasibility code is isolated in a test-only Emscripten archive; the unpromoted
polynomial implementation does not enter current public browser products.

The full WASM build and both exact Emscripten tests pass. Existing WASM and
TypeScript compatibility tests pass against the retained promoted browser
artifacts. Validation also exposed that the historical reviewed JavaScript
working-tree hash was never committed or retained, whereas its paired accepted
WASM hash is reproducible. The manifest preserves that historical hash and
relocks the JavaScript distributable to its reproducible committed bytes; this
evidence repair requires independent acceptance with this slice.

This is not full exact-backend completion. Irreducible factorization,
resultants, algebraic arithmetic/equality/order, construction DAGs, canonical
scalar/artifact codecs, malformed vectors, and production solver integration
remain blocked behind later slices.
