# Log: analytic-planar-boolean-promotion

# Promotion slice 2b: analytic operand lowering (regions, disks, annuli)

Second sub-slice of slice 2: lowering of packet-validated operands into
exact atomic boundary curves with coverage occurrences and canonical
source references, feeding the existing exact arrangement -> stages ->
regions -> provenance -> normalization chain. Capsules and swept paths
stay deferred to sub-slice 2c.

## Changes

- New `src/cpp/lib/geometer/analytic_operand_lowering.h` +
  `src/cpp/lib/analytic_operand_lowering.cpp`:
  `lower_analytic_job_geometry(arena, records, job_index)` lowers every
  operand owned by one job. Errors are job-local and map one-to-one to
  governed `[operation_diagnostic]` classes (`invalid_topology`,
  `invalid_arc`, `unsupported_geometry`, `resource_limit_exceeded`);
  failures return no partial value and never affect sibling jobs.
- Coverage ids are packet operand ids; occurrence ids are allocated
  densely from one in owner-traversal order; every occurrence gets an
  `ExactOccurrenceSource` (authored segment/curve ids for rings, compact
  feature roles 16/17 with whole-feature key 0 for disks/annuli).
- Authored ring winding is accepted in either direction and resolved with
  exact predicates only: the ring's lexicographic minimum is located
  among integer vertices and irrational arc-leftmost candidates
  (`cx - sqrt(r^2)` via `ConstructionBuilder` comparisons); an
  arc-interior minimum reads the travel direction, a vertex minimum reads
  the exact tangent turn, and the vertical collinear case reads the
  descent direction. Emitted `material_on_left` flags always describe the
  operand interior relative to each occurrence's travel direction, and
  membership `agrees_with_carrier` is computed against the canonical
  carrier (positive first nonzero tangent for lines, counterclockwise
  for circles).
- Full circles (disk boundary, annulus outer/inner) lower as the exact
  two-half-arc convention: split at the circle's leftmost/rightmost
  points, both halves counterclockwise, minor flags false; the annulus
  inner circle stays counterclockwise with `material_on_left = false`.
- Arc coherence: endpoints must be exactly equidistant from the center
  with nonzero radius, and the authored `major_arc` flag must equal the
  branch derived from the traversal direction (semicircles are
  `major = false`), else `invalid_arc`. Zero-length segments and a cusp
  at the ring minimum are `invalid_topology`.
- Job-local limits: authored coordinate span per axis <= 10^12 nm and
  <= 131072 occurrences per job, both reporting
  `resource_limit_exceeded`. Disk/annulus extremes are computed in exact
  integers, so extreme centers cannot overflow.
- Build wiring: added to `GEOMETER_EXACT_SOURCES` and the native-only
  `GEOMETER_LIB_SOURCES` append (not the browser wasm library); browser
  WASM dist artifacts stay byte-identical.
- New test `tests/cpp/analytic_operand_lowering_test.cpp`: unit coverage
  of curves/coverages/sources for ccw and cw squares, square with two-arc
  circular hole, arc-leftmost clockwise half-disc, disk, annulus, and
  multi-operand occurrence allocation; end-to-end pipeline runs
  (arrangement -> union stage -> regions -> provenance -> normalize)
  proving winding-insensitivity (ccw and cw squares normalize
  byte-identically), disk vs authored two-arc circle equivalence, and
  annulus hole topology; job isolation (capsule job fails
  `unsupported_geometry`, sibling disk job lowers); all four diagnostic
  classes; span boundary at exactly 10^12 (pass) and 10^12 + 1 (fail);
  occurrence budget overflow at 131073 segments. The wasm test target
  gets `ALLOW_MEMORY_GROWTH` for that last case.

## Interpretation decisions flagged for review

- Coordinate span is computed over authored coordinates (ring vertices,
  arc centers, feature center +/- radius), not arc bulge extremes; span
  and occurrence-budget violations classify as `resource_limit_exceeded`.
- The authored `major_arc` flag is validated against the
  direction-derived branch (`invalid_arc` on mismatch) rather than
  ignored.
- Membership `agrees_with_carrier` semantics were confirmed against
  `exact_arrangement_classification.cpp` (carrier-relative, with
  `material_on_left` occurrence-relative) and are differentially
  validated by the winding-insensitivity signature test.
- Provenance requires `ExactBooleanOperand.source_id` to equal the
  packet operand id (`normalize_operands` matches it against
  `source.operand_id`), settling the source-id question deferred to the
  orchestrator sub-slice: stage operands will reference the operand id
  under both the coverage and source roles.
- Geometry kinds 4 (capsule) and 5 (swept path) report
  `unsupported_geometry` until sub-slice 2c.
- Region hole containment, ring self-intersection, and cross-operand
  interactions stay with the arrangement/classification stage in the
  orchestrator sub-slice; lowering validates only per-segment and
  per-ring rules per the design failure-scope matrix.
