# Geometer 2026.9.18

Release identity: `v2026-09-18`; Python/runtime and Rust/TypeScript client
version `2026.9.18`; C ABI generation `20260918`.

## Static native SDK and unified transports

Every native release target now builds a separate static C ABI SDK candidate
containing the Geometer archive, exact private OCCT link closure, relocatable
CMake package, manifests, integrity inventory, provenance sidecar, and license
bundle. Windows uses an isolated MSVC `/MT` OCCT profile; the normal executable
and PyPI wheel retain their existing runtime profile.

The SDK gate packages and runs a direct-static Rust illustration sample from an
unrelated directory with executable discovery disabled. It produces SVG through
the in-process client and is rejected if a sibling `geometer(.exe)` is present
or Geometer/OCCT is dynamically imported.

The generic native C ABI and executable IPC server use the same native operation
catalog and dispatcher. One process-wide execution lane serializes native
geometry calls across supported entry points. The new process-terminal
`geometer_serve_stdio()` bootstrap lets an application expose the existing IPC
protocol from a hidden child command without shipping a sibling Geometer
executable.

Release production rebuilds the Windows x64, Linux x64, Linux ARM64, and macOS
ARM64 native archives and install-tested `wn-geometer` wheels, builds WASM, and
qualifies all four static SDKs from relocated external consumers. GitHub assets
and PyPI publishing depend on the same exact fail-closed inventory; published
assets are not overwritten in place.

Release CI is manual-only and requires its dispatch ref and exact existing tag
input to match, binding GitHub provenance to the released commit. It attests and
uploads the qualified inventory to a draft, verifies the downloaded draft,
publishes exactly the four rebuilt platform wheels through PyPI trusted
publishing, and only then promotes the GitHub Release. Public assets are
downloaded once more for exact digest and GitHub attestation verification.
