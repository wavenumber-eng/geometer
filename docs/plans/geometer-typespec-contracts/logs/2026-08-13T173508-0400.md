# Log: standalone diagnostic path identities

Focused re-review found that expanding packed diagnostic path tokens into RFC
6901 pointers was not deterministic from a standalone result packet. The packet
contains trusted job, stage, operand, and geometry IDs but does not contain the
original request's array indexes, and relationship path tokens cannot identify
one query from the job-scoped diagnostic record.

The logical job diagnostic now exposes an optional governed
`JobDiagnosticPath` identity instead of an RFC 6901 pointer. Packed token zero
maps to absence and each nonzero token maps one-to-one to the same-named enum
member. This projection is stable without the original request. Generated
convenience code may use an available request to present a navigable location,
but that presentation is not canonical contract data. Batch-rejecting outer
contract diagnostics continue to use the common `DiagnosticA0.path` RFC 6901
field while the request document is available.

The candidate checker now asserts the exact numeric token table, the exact
same-name logical enum inventory, optionality, DTO type, and packed-field
annotation. The earlier under-specified pointer-pattern table was removed.

governed vectors pass; focused manifest tests pass 10/10; Ruff, Pyright, Biome,
diff checks, and wn-dev-std 2026.8.12 repository/docs.plans audits pass.
