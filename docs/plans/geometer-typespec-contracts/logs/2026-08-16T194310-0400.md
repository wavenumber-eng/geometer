# Log: filtered-analytic-solver-design

# Isolate the exact oracle and add governed query-free batch assembly

Separated the algebraic feasibility/oracle implementation from the production
library. Native and WASM test builds now provide `geometer_exact_feasibility`
for exact differential and promotion-oracle tests, while `geometer_lib` no
longer compiles the exact sources, analytic operand oracle lowering, Boost, or
the exact topology validator. Production-neutral request and result packet
tests continue to link the production library.

Added an owned, not-yet-dispatched query-free filtered batch entry point. It
validates canonical request records, runs lowering and the governed broad phase,
builds records-only per-job filtered packets, preserves job-local governed
failures, and merges successful and failed job closures into one canonical
result packet. Global source references and source sets are remapped with fixed
sort keys and the governed prefix sequence interner; topology remains job-major
and is encoded once. Relationship queries remain an explicit outer unsupported
result until the separate indexed relationship evaluator lands.

The new orchestration keeps per-job and aggregate memory authority separate.
Lowering, broad phase, narrow/overlay/arrangement, face selection, regions,
lineage, outcomes, normalization/replay, and packet publication now propagate
explicit required-memory witnesses. This distinguishes proven aggregate-memory
exhaustion from per-job work/count exhaustion without a clamp-origin guess.
Known merge work and memory are pre-admitted before allocation, retained vector
capacities are accounted target-independently, and validation/resource failures
never publish partial batch bytes.

Tests cover mixed successful/failed jobs, nontrivial annulus topology and event
rebasing, zero-length range canonicalization, relationship gating, exact and
one-short per-job versus aggregate limits, work/count failure scope, direct
stage memory witnesses, 1x/2x empty and nonempty scaling, and native/WASM parity.
The algebraic fallback count remains zero. Relationship evaluation, operation
metadata/dispatch, attachment transport, and the final release gates remain
pending.
