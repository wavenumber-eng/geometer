# Independent plan review - 2026-09-20

Three independent read-only reviews covered build architecture and cycle time,
implementation readiness, and release/security provenance. The reviewers agreed
that the build-once/promotion-only direction is feasible, but rejected broad
execution until the plan corrected the following blockers:

- candidate bytes must embed the final synchronized date version, ABI, release
  date, notes, and expected tag even when the Git tag object is created later;
- one canonical candidate root must bind source, version, workflow, policy,
  OCCT lock, lane recipe, artifacts, and validation ledgers;
- credentialed ingestion and promotion must execute protected canonical workflow
  code and treat candidate/tag contents as hostile data;
- self-hosted public-repository builds require one-job JIT runners in disposable
  machine boundaries rather than labels, manual dispatch, or WSL separation;
- R2 intake, qualified candidates, promoted releases, tag aliases, credentials,
  retention, and locks require distinct authority and lifecycle rules;
- `geometer_hlr_preview` is current release content and cannot be removed as a
  low-risk build optimization;
- test-runtime and command/ID equivalence must be audited before deleting
  apparent duplicate CI lanes; and
- hosted ARM qualification must not depend on the constrained MacBook fallback
  while GitHub remains the selected ARM default.

The plan now incorporates those findings. The approved first execution slice is
limited to non-semantic instrumentation and preflight work: a canonical
candidate-root schema, timing/build-test ledger, pure promotion-decision fixture,
and early non-mutating orchestration tests. Current release bytes, preview,
test lanes, CMake/Cargo limits, OCCT fallback, and publication behavior remain
unchanged during this slice.

The identity portion of that recommendation was subsequently simplified during
implementation. The exact source commit already binds the checked-in workflow,
policy, and recipes, so the candidate root now contains only source, release
identity, and OCCT-lock digest. Workflow/toolchain observations remain evidence;
they are not independent cache or candidate identities.
