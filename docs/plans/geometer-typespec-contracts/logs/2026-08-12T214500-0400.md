# Log: generic ABI first implementation review remediation

Independent review of `45291ca16538b3a072f05219019b69ddc2ac1aa0` found two
blocking enforcement gaps and three focused follow-ups. The remediation adds a
named response validator before result ownership transfer. It enforces the
8 MiB response JSON maximum, 16-output count, nonempty/unique UTF-8 names,
nonempty UTF-8 media types, catalog declarations, 128-byte text bounds,
256 MiB individual payload bounds, and native/WASM aggregate limits before any
accessor narrows a size to `uint32_t`.

Generated string encoders now validate UTF-8 before RapidJSON writes. A
governed hex fixture represents invalid raw UTF-8 without adding a non-UTF-8
repository source file, and native regression coverage proves invalid native
diagnostic text cannot be serialized. Generated unknown-field paths preserve
embedded NUL bytes and use length-aware RFC 6901 escaping. Dynamic attachment
names use the same slash/tilde escaping.

Input descriptors with empty attachment names or media types are rejected
before constructing C++ strings. The runtime operation catalog and output
attachment declaration lookup are now generated directly from the normalized
catalog, and native tests parse and verify its response limits and complete
operation count.

Native validation passes all nine CTests. The full Emscripten build succeeds;
the wasm32 generic-operation smoke and retained STEP-to-GLB/packed-planar
smokes pass. Contract freshness validates 20 governed vectors, focused
Python/TypeSpec/docs/WASM tests report 46 passed, and Ruff, Pyright, repository,
and plan audits pass. L99 remains non-green only because the active temporary
plan is intentionally present.
