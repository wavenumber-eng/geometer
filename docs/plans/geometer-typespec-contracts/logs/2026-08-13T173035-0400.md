# Log: analytic TypeSpec candidate drift remediation

Independent review of the isolated analytic TypeSpec candidate found three
logical-to-packed projection gaps. The compact source kind used a different
identity from the governed numeric catalog, logical diagnostics exposed the
packed integer path token instead of the promised optional RFC 6901 path, and
job-result digests lacked an explicit derived-field rule despite not occupying
the packed 48-byte job-result record.

The candidate now uses `compact_feature_role` consistently. Diagnostics expose
an optional logical path annotated for packed `path_token` projection, and the
numeric catalog defines an exhaustive token-to-pointer-pattern mapping with
token zero reserved for an absent path. Successful results now retain warning
diagnostics. Successful and failed job-result digests are annotated and
documented as required derived fields computed from the canonical standalone
packet closure; they are verified by encoders and are never serialized as an
independent result-table field. Logical source-set values remain inline and are
deterministically interned by the packed projection.

The candidate checker now locks the complete analytic model-field and one-of
union inventories, all fifteen nonzero uint64 identity spaces, every governed
numeric enum, all operation and contract diagnostics, reserved diagnostic
codes, every source-reference mapping, every diagnostic path token and pattern,
and the packed/derived property annotations. This keeps the candidate isolated
from production generation while making future semantic drift fail the normal
contract freshness gate.

Validation: the complete contract/package/documentation freshness gate passes
with 22 governed vectors; the focused manifest suite passes 10/10; Ruff,
Pyright, Biome, diff checks, and the wn-dev-std 2026.8.12 repository and
docs.plans audits pass. The analytic design step remains active pending focused
re-review and design-freeze reconciliation.
